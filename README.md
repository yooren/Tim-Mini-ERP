# Tim Mini ERP v1.0.0

> 一体化企业业务管理系统（ERP）—— 覆盖仓储、供应链、生产制造、质量管控、设备、人力资源、销售CRM、财务、物流运输等全业务链条，仓储管理（WMS）只是其中一个子系统。前端零依赖、双击即可运行；也可选配 Node.js 服务端数据库，实现多台电脑共享同一份数据。

![版本](https://img.shields.io/badge/version-1.0.0-blue) ![许可](https://img.shields.io/badge/license-MIT-green) ![出品](https://img.shields.io/badge/by-Tim%20Ren%20Studio-5b4eff)

## ✨ 核心特性

- 🏢 **全业务链条覆盖** — 仓储/生产/质量/设备/人力/销售CRM/财务/物流 等 30+ 模块，不是单一仓储工具，而是完整的企业级一体化业务管理平台
- 📂 **多账套管理** — 数据按账套隔离，支持多公司/多仓库独立运营
- 🔐 **细粒度权限** — 34 模块 × 8 操作权限矩阵，支持自定义角色；权限未配置时默认拒绝而非放行
- 🖨 **统一打印** — 10+ 打印模板，自定义公司 Logo/名称/纸张/字体
- 💾 **数据管理** — 完整备份/恢复/导出/导入，支持自动备份
- 🗄 **双模式数据存储** — 默认纯前端 localStorage 单机模式，零配置开箱即用；也可连接 `server/` 目录下的 Node.js 后端数据库，实现多端共享
- 🐬 **数据库可插拔** — 服务端默认用内置 `node:sqlite`（零配置），也可通过 `DB_TYPE=mysql` 切换到独立部署的 MySQL/MariaDB，两者接口一致、随时可切换，详见[部署指南](docs/部署与配置指南.md#7-数据库配置与升级路径)
- 🔄 **版本升级** — 参照传统进销存软件的做法，厂商打包升级包、客户在系统里本地上传即可完成升级，不依赖联网检查更新；升级前自动备份，支持一键回滚，详见[部署指南](docs/部署与配置指南.md#10-版本升级)
- 🎨 **主题切换** — 多种主题配色方案
- 📥 **入库单支持多商品一次录入** — 与出库单一致，一张入库单可添加多行不同商品，共用仓库/供应商/日期，提交后各商品独立生成入库单据、独立审核
- 🖼 **登录页风格切换** — 内置经典分屏(蓝)/简约居中(绿)/科技暗色(黑白) 三种风格，各自独立配色；开机欢迎页与登录表单页配色联动，在「系统设置 → 系统信息」中可实时预览并一键切换，不影响当前登录状态
- 📱 **扫码支持** — 扫码枪自动识别填充
- 🚀 **零部署门槛** — 不依赖服务端时，双击 HTML 即可运行

## 🚀 快速开始

### 方式一：纯前端单机模式（最简单）

```
双击「TimMiniERP.html」

默认账号：admin / 123456
```

### 方式二：连接服务端数据库（多端共享数据）

```bash
# 1. 启动后端（首次需安装依赖）
cd server
npm install
npm start
# 默认监听 http://localhost:3000

# 2. 用任意静态文件服务器打开前端（不能直接用 file:// 协议访问后端接口）
cd ..
npx http-server -p 8080
# 浏览器访问 http://localhost:8080/TimMiniERP.html

# 3. 登录后进入「系统设置 → 系统信息」，填写后端地址并点击"连接并同步"
```

详见 [部署与配置指南](docs/部署与配置指南.md)。

## 🗄 数据存储

### 本地模式（默认）

系统使用浏览器 localStorage 存储数据，支持多账套隔离：

```
全局配置：wms_sysName, wms_theme, wms_printSettings ...
账套数据：wms_{accountId}_users, wms_{accountId}_goods ...
```

> ⚠️ localStorage 容量有限（5-10MB）。数据量大或需要多人共享数据时，请连接 `server/` 后端数据库，详见 [部署指南](docs/部署与配置指南.md#7-数据库配置与升级路径)。

### 服务端模式（可选）

连接后端后，账套业务数据（商品/出入库/生产/质量/财务等 48 个集合）会与服务端 SQLite 数据库双向同步：本地写入后台异步推送到服务端，登录/切换账套时从服务端拉取最新数据。系统名称、主题、打印设置等全局配置仍保留在本地，不参与同步。

## 🔧 技术栈

**前端**
- HTML5 + CSS3 + Vanilla JavaScript (ES6+)
- localStorage 数据持久化
- Lucide Icons (CDN)
- 零依赖，无需构建

## 📝 版本说明（v1.0.0）

本次发布对代码库做了一轮全面检索与逻辑验证，修复的问题包括：

- **权限矩阵默认放行漏洞**：`hasPerm()` 此前在权限未配置时默认允许操作，且新账套/新角色从不写入默认权限，导致 staff/viewer 角色事实上拥有全部权限。现已改为默认拒绝，并在账套初始化时自动写入安全默认矩阵；页面级访问控制（`canAccessPage`）也已接入实际路由。
- **库存数据一致性问题**：仓库调拨在库存不足时仍会静默放行并产生"凭空增加库存"；入库/出库单编辑与删除时存在 `DB.update()` 调用参数错误导致的静默不生效问题，修复后编辑会正确重算金额与库存、删除会正确回滚分仓库存。
- **旧版本升级兜底**：从没有仓库/权限矩阵数据的旧版本升级时，新增自动兜底迁移，避免功能性数据永久缺失。
- **数据库配置**：新增可选的 `server/` Node.js 后端与前后端同步层，替代此前仅停留在文档示例层面的数据库方案。
- **操作级权限校验补全**：此前仅仓库调拨/仓库管理模块的新建/编辑/删除/审核等操作接入了权限矩阵校验，其余 27 个业务模块完全没有校验（即使权限矩阵配置了也不生效）。现已为全部业务模块的新建/编辑/删除/审核/导入/导出等 200+ 处操作补齐 `hasPerm()` 校验，并在真实浏览器中验证了管理员/只读用户的实际操作结果。
- **账套切换会清空数据的严重问题**：此前每次切换账套（哪怕是切回一个已经用了很久、存了大量真实数据的账套）都会清除该账套的"已初始化"标记，导致下次进入时被内置示例数据整体覆盖，表现为"数据无故消失、回到最初的演示数据"。现已修复：只有账套第一次被使用时才会初始化数据，之后无论怎么切换都不会影响已有数据。
- **默认账套改为"演示账套"，新建账套不再带示例数据**：内置的 `default` 账套现在明确标注为"演示账套"（预置示例数据，供体验功能用）；管理员新建的账套现在是真正的空白账套，只包含一个可登录的管理员账号，不会像之前那样被自动填入商品/供应商/客户等示例数据，避免示例数据和真实业务数据混在一起。
- **数据库支持独立 MySQL**：服务端数据访问层拆分为 `db-sqlite.js`/`db-mysql.js` 两个实现（接口一致，`server.js` 统一改为 `async/await`），通过 `server/.env` 里的 `DB_TYPE=mysql` 即可切换到自己部署的 MySQL/MariaDB，无需改代码；SQLite 仍是零配置默认方案。
